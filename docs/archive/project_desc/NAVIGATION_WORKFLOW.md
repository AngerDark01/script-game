# 导航模式工作流程详解

本文档旨在详细梳理“导航模式”的完整工作流程，确保在加载地图后，能够100%复现绘制时的环境配置，并实现对导航参数的独立控制、实时微调和持久化保存。

## 一、 核心目标

1.  **环境复现**: 加载地图时，必须将 `config.json` 中的所有参数正确应用到 `NavigationCore`, `MotionController` 等核心模块。
2.  **独立控制**: 在“导航”UI标签页中提供一个独立的参数面板，其数值与“绘制地图”页面的参数完全解耦。
3.  **实时生效**: 对独立参数面板的任何修改，都应立刻对当前的定位和鼠标控制产生影响。
4.  **持久化**: 用户可以将微调后的导航参数覆盖保存回当前地图的 `config.json` 文件中。

## 二、 工作流程详解

### 阶段一: 加载与初始化 (用户点击“加载地图”)

这是确保环境一致性的奠基步骤。

1.  **读取配置**: 程序首先完整读取 `config.json` 文件，将其所有内容加载到一个专用于导航的内存字典中（例如 `nav_config`）。

2.  **参数注入**: 程序根据 `nav_config` 的内容，对核心组件进行初始化和参数配置。
    -   **注入 `NavigationCore` (定位核心)**:
        -   加载 `map_data.npz` 地图数据。
        -   **关键**: 将 `config.json` 中所有与 `Recognizer` 相关的参数（HSV范围、算法开关、数值等）通过 `nav_core.recognizer.set_params()` 方法，完整注入到 `NavigationCore` 内置的 `HSVRecognizer` 实例中。
        -   设置 `draw_scale` 和 `center_offset_y` 属性。
    -   **注入 `MotionController` (运动控制)**:
        -   通过 `motion_controller.set_screen_params()` 方法，设置 `monitor_center`, `y_bias`, `center_offset_y` 等参数。
    -   **注入 `MainWindow` (主窗口/UI)**:
        -   设置 `monitor_center` 和 `monitor_size`，为后续的截图和黄框预览做准备。

3.  **UI反馈**: 
    -   **填充参数面板**: 将 `nav_config` 中的可调参数（如 `y_bias`, `center_offset_y`, HSV值）显示在“导航参数面板”的对应控件上。
    -   **显示只读信息**: 在UI上展示 `monitor_center`, `draw_scale` 等从配置中加载的、不应修改的基础信息。
    -   **渲染与预览**: 在界面上渲染大地图，并根据加载的参数在屏幕上绘制黄色预览框，直观反馈当前的截图区域。

### 阶段二: 开始导航 (用户点击“开始导航”)

1.  **启动线程**: 一个独立的 `NavigationThread` 线程被启动，开始执行核心的定位循环，以防UI阻塞。

2.  **定位循环 (后台自动执行)**:
    -   **`capture`**: 根据已加载的 `monitor_center` 和 `monitor_size` 参数，从屏幕截取小地图的实时图像。
    -   **`localize`**: 这是定位的核心步骤。
        1.  调用 `nav_core.localize(screenshot)`。
        2.  `NavigationCore` 内部的 `HSVRecognizer`（已配置了正确的参数）对截图进行特征提取，生成“特征图”。
        3.  `NavigationCore` 使用模板匹配等算法，在全局大地图上寻找这张“特征图”的位置。
        4.  根据匹配结果和 `center_offset_y` 参数，计算出玩家在全局地图上的**精确坐标** `(x, y)`。
    -   **`update UI`**: 将计算出的新坐标 `(x, y)` 发送回主线程，更新UI上代表玩家的红色图标的位置。

### 阶段三: 交互与控制 (导航过程中)

1.  **地图点击 (寻路)**:
    -   用户在UI的地图上点击一个目标点。
    -   `MotionController` 接收到目标点的地图坐标。
    -   `MotionController` 根据玩家当前位置和目标位置，计算出移动方向的向量。
    -   **关键**: `MotionController` 使用已配置的 `y_bias` 和 `center_offset_y` 等校准参数，将地图上的移动向量精确地转换为屏幕上的鼠标点击坐标，并执行点击操作。

2.  **实时参数微调**:
    -   用户在“导航参数面板”上调整一个值（例如，修改 `y_bias`）。
    -   UI控件的信号（如 `valueChanged`）被触发。
    -   程序**立即**将这个新值更新到 `MotionController` 或 `NavigationCore` 中。例如，`y_bias` 的改变会立刻影响下一次鼠标点击的计算。
    -   UI状态标签提示“有未保存的修改”。

3.  **保存参数**:
    -   用户点击“保存当前导航参数”按钮。
    -   程序将当前“导航参数面板”上所有的值（即 `nav_config` 字典的最新状态）完整地写回 `config.json` 文件，实现对旧配置的覆盖。

---

此流程确保了从加载到执行的每一步都使用了正确的参数，并实现了您所要求的**独立参数控制、实时生效和持久化**。整个导航过程都在一个与“绘制地图”时完全一致的“数字孪生”环境中运行，从而从根本上解决了配置不一致导致的所有问题。
