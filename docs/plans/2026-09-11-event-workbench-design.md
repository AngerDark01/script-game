# 通用事件工作台设计（已确认）

日期：2026-09-11。代码基线：`4025221`。状态：设计确认，首批基础任务已实现；本文描述整体目标，不代表现有软件已具备全部能力。

## 1. 需求边界

用户通过工作台定义手柄事件、事件组和触发规则。跟随也是一种持续事件，与技能、周期按键、回城处于同一编排层。事件内容与触发来源、执行电脑和手柄分离，可复用、可组合。

- 普通按键只按配置的按下、保持、松开、间隔执行。**不增加技能画面识别、截图、释放成功确认或视觉重试。**
- “执行完成”只表示配置动作已完成，不表示游戏内释放成功。
- 跟随继续使用已有定位和规划；普通按钮事件不要求地图、人物位置或领导者位置有效。
- B 可以只手工操作、共享位置、发送事件，无需开启 Xbox 映射。
- A 的 Controller 1/2 各有独立运行实例、路径规划、暂停和故障状态。
- 复用已有驱动、宿主、输入安全机制、配对传输、动作契约、事件注册及工作台主题。旧导航识别事件保持原行为，不将其强行迁入新工作台。

## 2. 自底向上的组成

| 层 | 职责 | 复用与增量 |
|---|---|---|
| 基础动作 | 按钮、按钮组合、摇杆、扳机、释放 | 复用 `core/actions/contracts.py`、`gamepad.py` 和虚拟手柄宿主 |
| 定时序列 | 保持、等待、有限序列、周期调度 | 扩展 `core/events/follow_chain.py`；定时不阻塞线程 |
| 行为事件 | 按键序列、持续跟随 | 复用 EventDefinition/Handler/Registry；跟随适配现有 FollowerController |
| 组合运行时 | 顺序、并行、临时插入、资源冲突、取消 | 从 DualFollowSession 的内嵌事件调度中提取；最终仅一个输出拥有者/手柄 |
| 触发和路由 | 来源电脑、快捷键/界面、操作、目标电脑及手柄 | 扩展已有 LAN share 与本地控制，不新建配对协议 |
| 工作台 | 编辑、绑定、授权、状态、版本配置 | 复用现有跟随页和主题；将事件配置从地图配置中解耦 |

跟随是业务上的事件；不为追求接口统一给普通事件伪造地图位置，也不复制现有定位/寻路算法。

## 3. 事件、事件组、规则

### 3.1 事件定义

稳定 ID、显示名称、类型、动作轨道、默认执行策略、超时。一个事件由多个可并行的按键轨道组成，允许持续按键、频率按键和单次按键同时开始。

每条按键轨道支持：持续按下（按钮/组合、保持时长、按下间隔）、按频率重复（首次时机、间隔、每次保持时长、轨道结束时间）和单次执行。整个事件支持执行次数、循环或结束时间；多个限制同时存在时取最先满足者。循环事件必须有手动停止、结束时间或上层取消，禁止无界实例。

单次轨道可以与持续轨道并行，单次组合键也可以与持续单键或持续组合键并行。输出合并器按按钮归属合并按下状态；同一按钮的边沿冲突按优先级和排队/暂停规则处理。LT/RT 按模拟扳机值处理，LS/RS 点击与摇杆方向明确区分。

周期执行配置首次执行时机、间隔、每次保持时长、轨道结束时间、次数或持续至停止。默认固定起始节拍；错过节拍跳过，不追赶补发；上一轮未结束时默认跳过本轮，不堆积实例。使用执行端单调时钟。

持续跟随的“启动成功”和“事件结束”必须区分。顺序组里启动跟随后继续下一步，不能默认等待跟随自然结束导致后续步骤永远不执行。

### 3.2 事件组

- 顺序：按顺序执行，有限事件可等待完成，持续事件可启动后继续。
- 并行：启动多个子事件；停止组只停止这个组拥有的实例。
- 临时插入：暂停指定实例、执行插入事件、按条件恢复。
- 文件夹只用于整理，不具有执行语义。配置拒绝循环引用、无界嵌套和无限队列。

### 3.3 触发规则

来源设备集合 + 本地快捷键/界面操作 → 开始/停止/切换/执行一次 → 事件或组 ID → 目标设备及 Controller 1/2。

规则与事件定义分开。同一个技能可绑定不同规则，不用复制步骤。接收端只执行本地已保存且明确授权的定义；远程不能传脚本或任意步骤让接收端执行。

配置保存后默认停止。加载配置不等于授权运行。F7/F8 保留现有对应手柄控制，F9 保留急停，事件快捷键需检查冲突。

## 4. 并行、插入和输出归属

| 用户选择 | 行为 |
|---|---|
| 边走边释放 | 跟随输出 LS，技能输出按钮；不冲突的通道合并成一个完整手柄状态 |
| 停下释放再继续 | 暂停跟随输出并立即回中；技能按时间执行；完成后依据最新有效位置重新规划 |
| 停止跟随后执行 | 停止跟随，再执行回城等序列；不自动恢复 |

合并器按事件实例记录占用。一个事件释放 X 只移除自己的 X，不能清除另一个事件仍保持的 X。需要独立点击边沿的同按钮序列不能直接合并，应排队或暂停冲突事件。摇杆/扳机冲突使用明确的优先级与排队/暂停规则，不将方向随意相加。

暂停恢复使用实例 ID 和状态代次：只恢复插入动作实际暂停且仍允许恢复的实例。手动停止、急停、断线、故障和新一代实例都能使旧恢复请求失效。嵌套插入不能提前恢复仍被其他插入暂停的跟随。定位更新可在暂停期间继续，恢复不得回放旧摇杆值。

按键事件与定位脱钩不等于绕过安全：仍受本地授权、事件期限、输出 TTL、连接策略和急停约束。定位失效清理跟随贡献，不应误清理有效的本地技能贡献。

每只手柄保留一个宿主 program lease。新运行时内部先合成状态，再调用已有输出通道；不让并行事件各自抢占整只手柄。物理映射和程序模式保持显式互斥，不在此设计中开放隐式混控。

## 5. 局域网执行

复用 TLS 事件和现有配对设备 ID、会话、新鲜度、去重机制。开始周期事件后，由目标电脑本地计时；网络不逐次传按键。

- 配对与执行授权分开；接收端指定允许的来源、事件和手柄。
- 指令带请求 ID、会话、目标、操作和有效期；不比较不同电脑的绝对单调时钟。
- 开始、停止、切换应解析为带实例/代次的幂等操作；重复或乱序消息不能重启旧实例。
- 远程控制实例默认断线停止并释放；恢复连接不重放、不自动恢复。无关本地事件不随任意远端断线一起停止。
- 界面分别显示已发送、接收端接受/拒绝、运行、完成/取消/失败；不是技能成功回执。
- 多目标分别显示结果，不宣称跨电脑帧级同步或全有全无执行。停止操作优先于一般开始队列。

## 6. 工作台交互

先在现有跟随页面内整理入口，不改其他业务页面。事件编辑与地图编辑独立，可以未配置地图就编辑、授权并运行普通事件。

1. **事件库**：列表显示名称、类型；详情用轨道卡片编辑“单次/持续/频率、按键/组合、保持时长、间隔、轨道结束时间”；事件底部编辑“执行次数/循环/事件结束时间”。预览显示各轨道时间线。
2. **事件组**：引用已有事件，明确标示顺序、并行或插入以及跟随恢复选项；不要求用户写 op/JSON。
3. **触发与执行**：选择“哪个电脑上的哪个按键 → 哪个事件 → 哪些电脑的哪些手柄”，提供目标勾选和冲突提示。
4. **运行状态**：按电脑/手柄列出实例、来源、当前步骤、暂停原因、下一次执行和停止按钮；急停常驻。

典型配置：B 上一个快捷键启动 A 的双手柄跟随组；另一个触发 A1/A2 的技能；技能可边走边释放或短暂停步；回城组停止跟随和相关周期技能后按顺序发送手柄动作。

## 7. 迁移与验证

现有 `follow_chain.py` 已是无设备、无视觉依赖的有限序列执行器，优先扩展它，不另造按键序列引擎。定位耦合在 `dual_follow_session.py`，地图加载耦合还在 `follow_workers.py`；二者都要处理，否则未配置地图的技能仍无法运行。

旧 `chains`、`shortcuts`、`resume` 经显式版本迁移转换；保留旧配置版本，显示迁移摘要，不自动扩大远程授权。旧识别事件、输入同步 send/receive 和手动映射行为必须回归。

离线测试覆盖：无定位按键、组合键时序、错过周期不补发、同按钮持有归属、独立点击冲突、双手柄隔离、插入恢复代次、断线和重复指令、配置不自动启动。虚拟时钟测试不实际等待、不发送游戏输入。

真实验收另行执行：工作台实际启动、Windows spawn 工作进程、两台电脑路由回执、游戏聚焦后的双手柄动作及暂停释放。现阶段不能用离线通过宣称这些已完成。
