# 自动跟随：接线、验证与剩余现场验收

## 当前可用入口

工作台新增「自动跟随」页。仍由原统一启动入口启动工作台和手柄宿主。
页面默认不启动监视、更不启用手柄。程序输出使用原宿主里的独立短期租约；物理键鼠映射保持关闭。

### 双机配置顺序

1. 两端使用包含本次更新的软件/宿主；旧安装包不支持 `share` 和 `program.*`。
2. 在「虚拟手柄 → 局域网」将模式设为「位置与事件共享」，复用原设备码配对；授权需要的「接收位置」「接收事件」，建立连接。暂停/急停会撤销接收许可，重新连接要重新授权。
3. 两端选择同一地图包、同一墙体版本和同一定位参考墙选项；填写同一地图标识。程序还会比较墙体内容摘要，文件名相同而内容不同也不会盲目跟随。
4. B端选择角色B，配置**一个**角色，角色标识填 `B`（可修改，但须与A端 leader_actor 一致）。删除默认的另一个角色；B只监视并共享位置，不开启手柄。A端配置两个不同颜色/ID标记、不同控制器槽位。
5. A端填写B端设备ID，B端填写A端设备ID和目标角色标识（默认 `A1,A2`）。设备ID是配对后的固定设备身份，不是临时配对码。
6. 各端框选自己的小地图ROI。选择地图预览后，可在大地图圈出“小地图中心”大概所在区域；代码将它转换成左上角origin和有限搜索半径。右键/中键平移、滚轮缩放。没有隐式全图搜索。
7. 为每个标记设置HSV范围及面积上下限，或选择ID模板。不要把整个小地图当成一个颜色区域。墙体提取复用现有HSVRecognizer，可导入绘图时的识别参数。
8. 先「启动定位监视」，在诊断中确认角色坐标、地图内容摘要、局部定位有效、耗时稳定。此时**不会移动**。只有确认正确后，A端分别点角色「开启」。
9. 「暂停」释放程序输出；F7/F8会暂停对应已运行的手柄，F9宿主急停。若已暂停后再次按F7/F8，仍是原有键鼠映射开关行为，**不是**自动跟随恢复键。自动跟随必须通过页面重新开启。

事件链可自定义名称、开关、优先级、按钮/等待/条件/有限重试/模块钩子、总超时及是否恢复跟随。`follow.pause` / `follow.resume` / `follow.stop` 为保留事件。F10/F11默认对应暂停/恢复，仅对A端已手动开启的角色生效；F7/F8/F9不允许被事件快捷键占用。回城按钮序列须根据真实游戏由用户配置，本轮没有猜测按钮顺序。

配置保存为独立版本，加载历史版本不会运行；保存根目录由现有 `data_root` 决定。运行中请先停止监视再修改配置。诊断录制需显式勾选，最多每生产者1000条，不录制默认桌面全屏；录制文件夹在「运行诊断」显示，仍应注意小地图区域可能含私人内容。

## 模块与复用

| 层次 | 文件/目录 | 已有实现复用 |
|---|---|---|
| 地图与定位 | core/localization | 地图墙体版本、FrameContext、AffineTransform、phase位移、颜色/模板检测 |
| 目标与路径 | core/routing/follow_target.py、follower_planner.py、vector_tracker.py | 原A*、路径投影与插值；新增缓存网格/粗到细尝试；严格拐角检查仅跟随启用 |
| 程序设备输出 | core/actions/program_gamepad.py | 原VirtualGamepadClient、StickSlewLimiter、宿主StateStore与ReportLoop |
| LAN数据 | core/lan_follow、LanSyncService.SharedData.cs | 原设备身份/TLS/LiteNetLib；不占Controller槽位 |
| 事件 | core/events/follow_chain.py | 原EventDefinition/EventHandler/EventAction/EventRegistry/EventHookRegistry，不执行远程代码 |
| 运行时 | core/runtime/follower_controller.py、dual_follow_session.py、follow_workers.py、follow_service.py | 一个共享视觉进程、每角色一个规划控制进程；独立宿主报告周期 |
| UI | gui/modes/follow | 原主题、地图画布、屏幕ROI框选、工作台生命周期 |
| 回放 | core/diagnostics/follow_replay.py | 仅输入录制数据，不创建手柄设备 |

`emit`提供已有模块hook扩展点。默认工作台不注册任意外部插件执行器，也不把某个钩子名称当成Python代码。按钮步骤支持标准Xbox按钮及LS/RS点击；组合摇杆动作可从底层程序输出扩展，本版事件编辑器不含完整战斗宏图形语言。

## 安全约束

- A1/A2输入、路径、恢复、事件处理独立。旧坐标不重打时间戳。
- 网络位置寿命500ms上限；本地消费默认250ms。网络以接收方挑战时间保守计算传输寿命，不比较两台电脑的单调时钟。
- 事件带会话ID、期限和去重ID；换会话、定位丢失、超时优先取消事件。事件按钮输出期限也不能超过定位剩余有效期。
- 程序输出每次最多300ms（默认120ms），宿主以Windows uptime检查绝对到期时间；一秒无新状态租约失效。暂停、切换、F9撤销令牌，旧状态或急停前排队的启动不能重新开启。
- 规划/管道阻塞可能导致回中，绝不通过无限续期掩盖延迟。队列有界，位置只保留最新；控制事件队列满则停止。
- 静态墙体图上的可行性不能保证实际角色碰撞体完全相同；安全距离和脱困阈值仍需现场标定。

## 实际已运行的验证

最终相关Python组合回归：61 passed，包含真实spawn双规划进程测试、原墙体版本/定位回归、跟随配置/UI/输出/事件/回放。原手柄UI：45 passed、1 subtest。宿主：53 passed；LAN：20 passed（本机多实例TLS/UDP）。最终Release宿主构建0警告、0错误，现有开发工作台下次启动可加载更新。

双规划进程测试确实启动了两个Windows spawn进程，分别输入两个角色的位置，记录到两套不同方向的程序输出；输出端使用记录器，**没有操作真实驱动/游戏**。

可重复性能命令：

```powershell
python -m core.diagnostics.follow_benchmark
```

本机合成工作负载：1024×1024墙图、180×180小地图、搜索半径80、40帧；40帧配准成功，已知origin最大误差0像素。定位中位1.58ms/P95 1.65ms；长绕墙路径强制重算5次，中位17.85ms/P95 19.11ms；缓存查询中位0.015ms。原2倍网格同一负载重算约307ms；优化为粗网格优先、失败细化、复用原A*和不可变网格。该结果**不是**真实游戏精度/双机延迟承诺；窄通道回退精细网格仍可能明显变慢。

全tests目录尝试：一个既有测试按单文件导入包内相对引用导致收集失败（test_advanced_settings_file_io.py）；排除后259 passed、2 skipped、4 failed。失败是环境缺少pydirectinput发行包元数据，以及原PathFinder默认起点清障行为与3个旧测试预期不一致。本轮未改这些默认行为；跟随显式关闭起点清障，相关新测试通过。不能宣称全项目测试全绿。

## 尚待真实场景验收

- 真实小地图截图/颜色或ID模板、双方ROI、初始范围和比例。
- 两台电脑连接与内容摘要一致性；实际LAN往返、丢包/断线停止。
- 两个角色真实位置误差、碰撞尺寸/通道宽度、跟随距离、摇杆坐标基；真实撞墙后恢复时间。
- 用户配置的回城/技能链逐步验证，地图切换时必须停下重新匹配。
- 游戏窗口聚焦时的Controller1/2实际输入，以及旧键鼠映射模式启用/暂停/关闭的系统按键恢复。
- 本轮没有替换另一台电脑的安装包，没有修改防火墙，没有自动启动游戏控制。
