# 自动导航第一阶段设计

日期：2026-05-18

## 目标

在单张地图内，基于现有的小地图定位、A* 和鼠标点击移动能力，实现“从当前进入点稳定走到出口区域”的自动导航。

第一阶段只解决无干扰场景：

- 人物进入地图后自动定位并出发
- 支持为每张地图保存出口点
- 支持人工添加多个途经点约束路线
- 即使存在轻微定位抖动，也不乱点、不频繁重规划、不越走越偏

明确不包含：

- 事件识别与处理
- 战斗、拾取、弹窗自动处理
- 跨地图切换
- 全流程自动通关

## 背景与现状

当前项目已经具备以下基础：

- [`core/navigation_core.py`](../../core/navigation_core.py) 提供实时定位，已修正绘图与导航截图几何不一致的问题
- [`core/pathfinder.py`](../../core/pathfinder.py) 提供基于墙体图的 A* 寻路
- [`core/motion_controller.py`](../../core/motion_controller.py) 提供基于地图坐标差值的鼠标点击移动
- [`gui/modes/navigation_mode.py`](../../gui/modes/navigation_mode.py) 已有地图加载、实时定位循环、地图点击和监视窗口显示能力

当前缺口主要有三类：

1. 运行时导航决策缺失
当前只有“点击某个地图目标点后执行一次移动”，没有持续跟随、卡住恢复、分段规划和状态机。

2. 路线语义缺失
每张图没有“出口区域”和“人工途经点”的持久化配置，纯 A* 在部分岔路和复杂地形下不够稳。

3. 抗抖控制缺失
定位结果会有轻微波动，如果直接把每帧定位输出喂给点击控制，会导致目标点抖动、重复点击和越走越偏。

## 设计原则

1. 保持现有定位与截图几何一致性
导航只消费现有一致化后的截图与定位结果，不再引入额外偏移修正逻辑。

2. 人工点约束大方向，A* 负责局部可通行
人工点不是替代 A*，而是把全程路径拆成多个更稳的局部段。

3. 路径跟随优先，重规划保守触发
不要把“稍有波动就重算路径”作为常态。

4. 控制输入与原始定位解耦
允许定位器轻微抖动，但控制器不能每帧跟着抖。

5. 第一阶段架构需为第二阶段事件系统预留暂停/恢复接口

## 总体方案

采用“全局路径 + 局部跟随器 + 恢复状态机”的方案。

### 路径层

对于当前地图的一条主路线，数据结构为：

- 一个出口区域 `exit_region`
- 零个或多个人工途经点 `guide_points`

运行时按分段执行：

- 当前位置 -> guide_point_1
- guide_point_1 -> guide_point_2
- ...
- 最后一个 guide_point -> exit_region

每一段：

1. 用 A* 计算原始路径
2. 对原始路径做路径压缩和平滑
3. 把平滑后的路径交给局部跟随器

### 控制层

局部跟随器不按 A* 节点逐个点击，而是：

1. 把当前位置投影到当前路径上
2. 沿路径向前取一个前瞻点 `subgoal`
3. 按点击冷却和偏离情况决定是否发新点击

这样能显著减少左右来回修正。

### 恢复层

状态机负责：

- 等待稳定定位再出发
- 路径段切换
- 短暂丢定位时冻结控制
- 卡住时保守恢复
- 只有在必要时才触发重规划

## 路线数据设计

每张地图目录新增一个 `route.json` 文件，与现有 `config.json` 分离。

建议结构：

```json
{
  "version": 1,
  "routes": {
    "main": {
      "exit_region": {
        "center": [1234, 5678],
        "radius": 28
      },
      "guide_points": [
        [1100, 5200],
        [1180, 5400],
        [1210, 5550]
      ]
    }
  }
}
```

设计说明：

- `exit_region` 使用区域而不是单点，降低终点附近定位抖动带来的抖动修正
- `guide_points` 按顺序约束路线走廊
- 第一阶段只需要一条固定主路线 `main`

## 代码边界设计

### 1. `core/route_manager.py`

职责：

- 加载和保存 `route.json`
- 设置/读取出口区域
- 添加、撤销、清空途经点
- 返回当前地图的主路线数据

不负责：

- UI 渲染
- 寻路
- 点击控制

### 2. `core/path_utils.py`

职责：

- 删除共线点
- 直线 shortcut 平滑
- 计算路径累计长度
- 把点投影到折线路径
- 根据路径长度取得前瞻点
- 计算当前位置到路径的偏离距离

全部保持为纯函数。

### 3. `core/auto_navigator.py`

职责：

- 维护自动导航状态机
- 按段规划路径
- 消费 `NavigationCore` 的定位结果
- 维护 `raw_pos / trusted_pos / control_pos`
- 计算前瞻目标
- 控制重规划、卡住恢复和到达判定

不负责：

- 直接截图
- 操作 Qt UI
- 直接调用 `pydirectinput`

### 4. `gui/modes/navigation_mode.py`

职责调整为编排层：

- 地图加载时同步加载 `route.json`
- 提供路线编辑入口
- 根据编辑模式分流地图点击
- 渲染出口、途经点、当前段路径和前瞻点
- 在 `navigation_loop()` 中采集截图并调用 `auto_navigator`
- 根据 `auto_navigator` 返回的动作调用 `motion_controller`

## UI 与交互设计

在导航模式增加轻量按钮：

- `设置出口`
- `添加途经点`
- `撤销途经点`
- `清空路线`
- `保存路线`
- `开始自动到出口`

地图点击模式显式区分为：

- `NONE`
- `SET_HINT`
- `SET_EXIT`
- `ADD_GUIDE_POINT`

这样避免与现有“初始提示点”和“手动目标点击”冲突。

### 地图渲染新增元素

- `exit_region`：出口区域圆圈
- `guide_points`：编号途经点
- `planned_segment_path`：当前分段规划出的平滑路径
- `active_subgoal`：当前前瞻子目标

## 运行时状态机

第一阶段状态集合：

- `IDLE`
- `ACQUIRE`
- `PLAN_SEGMENT`
- `FOLLOW_SEGMENT`
- `SHORT_LOST`
- `STUCK_RECOVER`
- `ARRIVED`
- `FAILED`

状态语义：

### `IDLE`

未启动自动导航。

### `ACQUIRE`

进入地图后等待稳定定位。必须满足连续若干帧高置信定位，才允许出发。

### `PLAN_SEGMENT`

对当前段执行 A*，并立即做路径压缩与平滑。

### `FOLLOW_SEGMENT`

正常跟随当前段路径，依据前瞻点控制点击。

### `SHORT_LOST`

短时丢定位。暂停点击，短暂观察，不立即重规划。

### `STUCK_RECOVER`

确认在当前段上长期没有取得有效进度时，先保守恢复，再视情况重规划当前段。

### `ARRIVED`

进入出口区域后停止。

### `FAILED`

连续恢复失败，停止等待人工介入。

## 抗抖位置模型

运行时维护 3 套位置：

- `raw_pos`：定位器原始输出
- `trusted_pos`：通过置信度、跳变门限和连续性筛选后的可信位置
- `control_pos`：真正用于路径跟随的轻度平滑位置

更新规则：

1. 低置信度结果不更新 `trusted_pos`
2. 单帧大跳变默认拒绝
3. 连续多帧朝相近方向的小变化，才更新 `trusted_pos`
4. `control_pos` 基于 `trusted_pos` 做轻量平滑，不能过重

目的：

- 把定位噪声隔离在控制层之外
- 避免轻微抖动导致目标点击点持续变化

## 分段路径规划

### 分段目标生成

- 若有 guide points，则当前目标为“下一个未到达的 guide point”
- 若 guide points 全部完成，则目标为 `exit_region.center`

### A* 规划

继续复用 [`core/pathfinder.py`](../../core/pathfinder.py)。

### 路径平滑

对 A* 原始输出做两步处理：

1. 删除共线点
2. 基于 walkable 检测做直线 shortcut

理由：

- 减少锯齿折线
- 降低前瞻目标在密集节点间跳动的概率
- 降低发点击频率

## 局部跟随控制

### 前瞻跟随

每次更新：

1. 把 `control_pos` 投影到当前路径
2. 得到当前路径累计进度
3. 沿路径向前取一个 `lookahead` 距离
4. 得到 `subgoal`
5. 根据限频条件决定是否点向 `subgoal`

### 前瞻距离

前瞻距离应与当前监视窗口对应的相对视野一致，并设置上下限。

原则：

- 太小会导致沿节点抖动
- 太大会导致拐弯处切角过度

### 点击限频

即使每帧都刷新控制状态，也只有满足以下条件之一才允许发出新点击：

- 距离上次点击已经超过冷却时间
- 当前前瞻点相对上次点击目标前进了足够距离
- 当前偏离路径明显增大
- 上次点击后持续没有取得有效进度

核心目标：

- 不每帧点击
- 不因轻微定位波动重复点同一区域

## 重规划与卡住恢复

### 重规划触发条件

只在以下情况触发：

- 初次进入一段
- 当前段完成，切换到下一段
- 明显偏离当前段路径，并持续一段时间
- 持续没有沿路径取得进度
- 从短时丢定位恢复后，当前位置已不适合继续沿旧路径跟随

并且必须设置重规划冷却时间。

### 卡住判定

卡住不以“有没有移动像素”判断，而以“是否沿路径取得累计进度”判断。

记录：

- 当前路径进度
- 最近一次有效推进时间
- 时间窗内累计推进量

### 恢复顺序

1. 轻恢复：点击一个更近的保守前瞻点
2. 重恢复：重规划当前段
3. 连续失败：进入 `FAILED`

## 段切换与到达判定

### guide point 切换

不能只凭单帧距离阈值切段。

建议满足以下之一：

- 连续若干帧进入 guide point 到达半径
- 当前路径进度已越过段尾附近阈值

### 出口到达

进入 `exit_region` 即判定到达，不再追求单像素收敛。

## 第一阶段成功标准

以下条件同时满足才视为完成：

1. 单张地图可配置并保存一个出口区域
2. 单张地图可配置并保存多个 guide points
3. 加载地图时自动恢复该地图路线
4. 无干扰情况下，人物能从当前进入点走到出口区域
5. 轻微定位抖动时，不频繁点鼠标
6. 短暂丢定位时，优先冻结并恢复，不乱重规划
7. 整体轨迹朝出口单调推进，不出现明显左右摆动

## 对第二阶段的预留接口

虽然本阶段不处理事件，但 `auto_navigator` 必须预留：

- `pause(reason)`
- `resume()`
- `notify_external_interrupt()`
- `reset_with_current_position()`

这样后续事件系统接入时，只需要暂停导航、处理事件、恢复导航，不必推翻第一阶段结构。

## 实施顺序建议

1. 先做 `route.json` 读写与编辑 UI
2. 再做路径工具与分段规划
3. 再做 `auto_navigator` 状态机与抗抖控制
4. 最后接入 `navigation_loop()` 联调可视化和点击策略

这能最大程度降低风险，并让问题定位保持清晰。
