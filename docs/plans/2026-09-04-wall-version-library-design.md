# 墙体完整快照版本库设计

**日期：** 2026-09-04  
**状态：** 已确认  
**取代范围：** 地图编辑器原先的“加墙 / 擦墙掩码长期叠加”存储模型。

## 目标

墙体编辑器应以当前导航正在使用的墙体版本为编辑起点。编辑中的加墙和擦墙直接作用于一份内存草稿；预览始终展示这份草稿的最终墙体，而不是原始墙体上叠加红色/青色操作痕迹。

- 擦除白色墙体后，该区域立即显示为黑色空白；
- 编辑不会即时影响导航；
- 用户点击“确认并保存为新版本”后，才生成一个不可变的完整墙体版本；
- 用户可选择任一历史版本并将其设为导航版本；
- 导航只读取当前版本的一张完整 `wall_layer`，不再在导航加载时叠加 add/erase 掩码。

原始 `map_data.npz` 永远不改写。

## 文件布局

```text
map_data/<地图名>/
├─ map_data.npz                       # 原始绘制地图，包含基础 wall_layer
├─ config.json                        # 地图配置与版本索引
├─ wall_versions/
│  ├─ v0001.npz                       # 完整、最终的墙体快照
│  ├─ v0002.npz
│  └─ ...
└─ wall_overrides.npz                 # 仅保留旧格式备份；版本化后不再由导航使用
```

每个 `wall_versions/vNNNN.npz` 仅含：

```python
wall_layer: uint8[height, width]      # 0 为可通行空白，255 为墙体
```

`config.json` 新增的版本索引：

```json
{
  "wall_versions": {
    "format_version": 1,
    "active_version": "v0002",
    "versions": [
      {
        "id": "v0001",
        "file": "wall_versions/v0001.npz",
        "created_at": "2026-09-04T10:30:00+08:00",
        "parent_version": null
      },
      {
        "id": "v0002",
        "file": "wall_versions/v0002.npz",
        "created_at": "2026-09-04T11:15:00+08:00",
        "parent_version": "v0001"
      }
    ]
  }
}
```

配置中其他绘图、识别、导航字段原样保留。

## 生命周期

```text
加载编辑器
  └─ 当前 active_version 的完整 wall_layer
       └─ 复制到 working_wall_layer 草稿

加墙 / 擦墙
  └─ 只修改 working_wall_layer
       └─ 预览直接显示草稿：墙为白，已擦除区域为黑

确认并保存为新版本
  └─ 原子写入 wall_versions/vNNNN.npz
       └─ 原子更新 config.json 的版本索引与 active_version
            └─ 下一次导航加载直接读取 vNNNN

回退
  └─ 选中历史版本 → 设为导航版本
       └─ 只更新 active_version；历史快照不被覆盖或删除
```

编辑草稿不写入磁盘；“确认并保存为新版本”是用户明确确认擦墙/加墙的唯一提交点。撤销和重做只在草稿期生效。

## 编辑器交互

- 加载地图时默认检查出当前导航版本；没有版本时使用原始地图。
- 版本列表包含：`原始地图`（只读基线）和全部快照版本；当前导航版本明确标记。
- 切换基线前，如果草稿未确认，提示用户放弃草稿或先保存为版本。
- 加墙把草稿像素设为 `255`，擦墙设为 `0`。画布不绘制红/青操作层；鼠标画笔轮廓可保留为短暂辅助提示。
- “确认并保存为新版本”创建下一个递增版本并自动设为导航版本。
- “设为导航版本”只切换当前版本指针，不会复制、改写或删除历史版本。
- 保存/切换后提示：已经运行中的导航必须重新加载地图，才会读取新的版本。

## 导航加载边界

`core.localization.map_package.load_navigation_map_package()` 是唯一导航地图加载边界：

1. 读取 `map_data.npz` 中的其他地图字段；
2. 读取 `config.json.wall_versions.active_version`；
3. 如果当前版本存在，直接加载其完整 `wall_layer`；没有版本时直接使用原始 `wall_layer`；
4. 从上述单一最终墙体图派生 `nav_wall_layer`；
5. 定位和寻路共享同一份最终墙体图。

导航层不再读取或组合 add/erase 掩码。

## 旧修正层迁移

旧地图可能只有：

```text
map_data.npz + config.json.wall_overrides + wall_overrides.npz
```

第一次在新编辑器或导航加载此类地图时，系统安全地：

1. 按旧规则把原始墙体与旧 add/erase 掩码合成为最终墙体；
2. 将合成结果保存为 `wall_versions/v0001.npz`；
3. 将 `v0001` 设为 `active_version`；
4. 保留原 `wall_overrides.npz` 和其配置字段作为只读备份，不删除、不覆盖原始地图。

迁移后导航只读取 `v0001`，不会继续使用旧掩码。若迁移写入失败，不更新版本索引，并报告加载错误；旧文件保持完整，用户可在修复后重试迁移。

## 安全与性能

- 快照与配置均采用临时文件写入后原子替换；
- 版本文件路径必须受限于当前地图的 `wall_versions/` 目录；
- 加载时校验二维形状与基础地图一致，损坏版本不会被设为 active；
- 每次版本保存只写一张压缩二值墙体图，不复制 `canvas`、探索层或原地图包；
- 编辑过程复用局部矩形补丁用于撤销/重做，避免每次笔划复制整张地图。

## 验收条件

1. 擦除后画布在对应位置直接显示黑色空白，不显示青色掩码；
2. 当前导航版本是编辑默认基线；
3. 未确认草稿不会改变磁盘文件或正在运行的导航；
4. 确认后生成新的完整版本，旧版本字节内容不变；
5. 切换 active_version 后重新加载导航，定位和寻路均使用选定版本；
6. 无版本地图直接使用原始 `wall_layer`；
7. 旧掩码地图可安全迁移为 `v0001`，原始地图包及旧修正文件仍保留。
