# PoE2 动态版本指纹与安全布局探测

批准方案 B：每次初始化都对当前进程的可执行文件重新计算 PE/.text 指纹。已知版本保持现有快速路径；未知版本只在只读 AOB 找到 GameState 槽位、当前内存结构校验通过、地图元数据与 guard 一致之后，才建立本次会话。不把新指纹永久加入白名单。

## 边界

- 底层采集器负责可执行文件指纹、AOB 和结构校验；业务 UI 只展示成功或明确的拒绝原因。
- 未知版本的初始化必须从 AOB 候选开始，不能信任缓存的 RVA；后续同一会话捕获可使用已验证的 RVA，但仍检查进程身份、构建指纹及实时布局。
- 任何无候选、歧义、元数据不合法、guard 不一致或内存不稳定都拒绝初始化。只读访问，不发送任何游戏输入或网络同步。
- 现有 terrain 结构与双人组件结构属于不同契约：通过本方案只表示地形读取链验证，不保证任意新版本的双人坐标组件兼容。

## 验收

未知版本能以真实指纹建立临时会话；已知版本维持快路径；错误版本/错误布局必须拒绝；会话跨版本不能复用；聚焦测试通过，并在当前进程可用时执行一次真实只读初始化。
