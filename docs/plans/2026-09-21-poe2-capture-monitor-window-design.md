# PoE2 截图监控与对比样本窗口设计

## 目标

在 `PoE2 地形 -> 数据采集测试` 中提供独立的截图监控窗口，用于持续观察并一次性保存同一帧对应的原始小地图、预处理画面、匹配特征和当前完整地形，支持历史样本切换与相邻样本对比。

本功能只采集、展示和归档证据，不执行定位、路线规划、键盘、鼠标、Xbox、Host 或网络输入。

## 页面入口与窗口生命周期

- 数据采集测试页增加“打开截图监控窗口”按钮。
- 点击后打开独立窗口并自动开始持续刷新。
- 重复点击只激活已有窗口，不创建多个实例。
- 关闭窗口时停止窗口自有定时器并释放当前帧缓存。
- 主页面关闭或应用退出时同时关闭监控窗口。
- 窗口复用现有 `preview_provider`、PoE2 专属 recognizer、monitor config 和当前 terrain service，不创建第二套截图或识别引擎。

## 窗口内容

窗口展示四个同步视图：

1. 原始小地图截图；
2. 预处理画面；
3. 匹配特征；
4. 当前完整地形预览。

窗口提供以下操作：

- 开始监控；
- 停止监控；
- 手动刷新；
- 保存当前对比样本；
- 打开样本目录；
- 上一个样本；
- 下一个样本；
- 当前样本与上一个样本并排对比。

## 帧一致性

每次刷新只调用一次截图后端。原始图、预处理图和匹配特征都从该帧派生，并组成一个不可混用的当前证据帧。保存操作只能消费当前有效证据帧，不能重新截图，也不能在刷新失败后沿用上一帧。

当前完整地形来自测试页独立 `Poe2TerrainService` 的内存快照。保存时对该快照生成展示图；没有当前地形时仍允许保存前三张图，但必须在元数据中记录 `terrain: missing`。

## 样本目录与数据契约

样本根目录：

```text
data/poe2_live_terrain_test/samples/
```

每次保存创建不覆盖的目录：

```text
YYYYMMDD-HHMMSS-<area_id>-<area_hash>/
  raw.png
  processed.png
  feature.png
  terrain.png        # 仅当存在当前地形
  sample.json
```

`sample.json` 至少包含：

- 样本 schema 版本；
- 保存时间和截图时间；
- 地图区域、实例、尺寸及地形是否存在；
- 截图物理矩形、坐标空间、DPI、人物中心点；
- 正方形/圆形和半径；
- 地图旋转及水平/垂直翻转；
- recognizer 完整参数；
- 每张图片的文件名、尺寸、通道、数据类型和 SHA-256；
- 保存失败或缺失原因。

## 保存与失败规则

- 原始图、预处理图和匹配特征必须来自同一次刷新。
- 没有有效当前帧时拒绝保存。
- 刷新失败时立即清除当前证据帧和预览，不能复用旧帧。
- 使用临时目录写入全部文件，完成后原子重命名为最终目录。
- 任一步骤失败时清理临时目录，不留下可被历史浏览器识别的半成品。
- 目录名冲突时添加稳定递增后缀，不覆盖旧样本。
- 图片保存和 manifest 生成放在 PoE2 业务层的专用样本归档模块，UI 只负责收集当前证据和触发命令。

## 历史浏览与对比

- 归档模块按保存时间列出有效样本目录，只接受包含合法 `sample.json` 的目录。
- 上一个/下一个操作加载四类图片和摘要信息。
- 对比视图以“上一个样本”和“当前样本”并排显示相同图层；用户可在原图、预处理、特征、地形之间切换。
- 缺失地形时显示明确占位，不使用其他样本的地形补位。

## 分层边界

- 通用截图和识别能力继续由现有底层模块提供。
- PoE2 样本命名、地图实例元数据和 profile 参数归档保留在 `features/poe2/live_terrain/`。
- 独立窗口只位于 `ui/modes/poe2_live_terrain/`，不修改绘图模式。
- 测试覆盖纯归档契约、失败原子性、帧失效规则、窗口单例生命周期和页面关闭清理。
