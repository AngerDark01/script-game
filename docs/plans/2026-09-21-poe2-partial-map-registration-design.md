# PoE2 局部拼图到全局地图形状配准设计

状态：已确认，先在实验台验证，不接入正式运行时。

## 问题

PoE2 小地图连续截图可以拼成一块局部地图，内存读取可以得到完整原生地形。两者来自同一地图，但存在：

- 未知旋转角度；
- 未知统一比例；
- 未知全局平移位置；
- 可选的坐标镜像；
- 只有部分区域重叠；
- 拼图墙线和原生地图墙线粗细不同；
- 传送门、文字和累计拼图误差形成离群结构。

目标不是比较两张图片的像素，而是根据局部墙体形状与全局墙体形状的部分重叠，恢复二维相似变换：

```text
global_point = scale * rotation(local_point) + translation
```

必要时在旋转前加入水平镜像分支。变换一旦成立，旋转角就是地图方向，局部人物坐标经同一变换后就是全局位置。

## 范围

本阶段只新增离线实验台：

```text
tools/debug/poe2_partial_map_registration_probe.py
tests/poe2_live_terrain/test_partial_map_registration_probe.py
```

实验台只读取已保存的拼图会话和地形图片，输出 JSON 报告、候选叠图和候选总览。它不会修改：

- `src/auto_modules/core`；
- PoE2 正式定位 runtime；
- 第一页绘图模式；
- profile 参数；
- Xbox、键鼠、Host 或 LAN 链路。

只有算法通过合成测试和实机样本门槛后，才另写设计把稳定、游戏无关的能力下沉到 `core`。

## 输入契约

实验入口接收：

```text
--session <stitching-session-directory>
--terrain <terrain.png or capture-sample-directory>
--output <probe-result-directory>
```

拼图会话必须包含：

- `stitched_map.png`；
- `session.json`；
- `map_origin`；
- `current_position`；
- `draw_scale`。

地形输入可以直接是 `terrain.png`，也可以是包含 `sample.json` 和 `terrain.png` 的历史样本目录。若 session 自身带有 `terrain.png`，默认优先使用同会话地形。实验报告必须记录数据来源和 SHA-256，禁止静默借用无法证明属于同一实例的地图。

## 形状标准化

局部拼图和原生地图首先转换为统一的二值结构：

1. 根据灰度语义提取亮墙线；
2. 删除小于最小面积的孤立噪点，但不按“是否闭环”删除结构；
3. 使用形态学骨架把不同粗细的墙体压缩成单像素中心线；
4. 删除短毛刺；
5. 保留骨架包围盒与局部人物锚点之间的坐标变换。

原始拼图永远不被修改。骨架仅是派生的定位结构图。

## 候选生成

使用 OpenCV `GeneralizedHoughGuil` 在完整地形骨架中搜索局部骨架。该算法直接产生：

```text
center_x, center_y, scale, angle, votes
```

实验分两级：

1. 粗搜索覆盖完整角度和合理比例区间；
2. 取票数最高且空间分离的若干候选，在候选角度和比例附近细化。

镜像通过对局部骨架原图和水平镜像图分别运行相同搜索实现。垂直镜像可由“水平镜像 + 180° 旋转”等价表示，不增加第三分支。

广义霍夫只负责产生候选，不直接决定成功。

## 候选验证

每个候选把局部骨架投影到全局地形。最终分数采用厚度无关、允许离群点的对称 trimmed Chamfer：

- 正向：局部骨架到最近全局骨架的距离；
- 反向：候选实际观测范围内，全局骨架到最近局部骨架的距离；
- 两侧均裁掉最差的默认 `20%` 距离；
- 距离超过截断半径后不再继续增加惩罚；
- 传送门、文字和局部拼接污染因占比较小而成为离群点；
- 有效骨架点不足的候选直接拒绝。

评分还记录而不隐藏以下原始证据：

- 霍夫位置、角度、比例票数；
- 正向/反向 inlier ratio；
- trimmed mean distance；
- 有效骨架像素数；
- 第一名与第二名的分差；
- 镜像分支。

## 高置信验收

单一最高分不能称为方向已确认。实验结果只有同时满足以下条件才标记 `accepted=true`：

- 候选有效骨架点数达到门槛；
- trimmed 正向与反向覆盖达到门槛；
- 第一名相对第二名有足够分差；
- 从局部拼图裁出的至少三个空间分离结构块，独立搜索后支持相同角度、比例和镜像；
- 三块换算得到的全局平移与它们在拼图中的相对位移一致。

若地图中存在严格重复或对称区域，算法必须返回 ambiguous，而不是猜测。

## 精修

广义霍夫与 Chamfer 已确定正确候选后，可使用 `cv2.estimateAffinePartial2D(..., method=cv2.RANSAC)` 根据最近邻骨架对应点估计统一比例、旋转和平移。ECC 只允许作为最后的亚像素精修，不能承担全局搜索。

## 实验产物

输出目录包含：

```text
report.json
local_skeleton.png
terrain_skeleton.png
candidate_01_overlay.png
candidate_02_overlay.png
candidates_sheet.png
```

叠图颜色固定：全局骨架蓝色、投影局部骨架绿色、重合点黄色、人物位置红色。报告必须能从输出复现所有候选参数。

## 验证顺序

1. 合成厚墙/细墙数据验证骨架厚度不变性；
2. 合成部分重叠、已知旋转/比例/平移数据验证变换恢复；
3. 加入粗块、文字状线段和随机缺失，验证正确候选仍排第一；
4. 使用当前 `MapFlotsam:5C048CD0` 拼图和地形生成实机候选叠图；
5. 从同一拼图裁出多个区域验证方向一致性；
6. 只有通过后才讨论下沉通用引擎。

## 推广到通用引擎的门槛

实验能力只有同时满足以下条件才允许下沉：

- 合成数据的角度、比例和平移误差在规定范围内；
- 噪声占比达到 `20%` 时仍能拒绝错误候选；
- 同一实机地图至少三个空间块给出一致变换；
- 至少两个不同地图实例复现；
- 算法接口不包含 PoE、传送门、技能或页面术语；
- 失败结果显式表达 `no_match` 或 `ambiguous`，不返回伪坐标。
